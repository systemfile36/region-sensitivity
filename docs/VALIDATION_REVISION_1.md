# Revision 1 Validation Experiments

This document summarizes the additional experiments run for the first
revision of the SSAT paper (version 1.0.1). They test how the reliability
grade depends on its design choices, how SSAT behaves on more architectures,
how much the ImageNet preprocessing confound changes the results, whether
the NTU RGB+D body-part profiles agree with an external reference, how the
audit cost scales, and how SSAT compares with a Captum-based workflow in a
second setting.

Code, protocols, and results are under
[`experiments/revision_1/`](../experiments/revision_1/README.md). Every
experiment has a `protocol.json` (or `protocol.md`) committed before it ran,
a `summary/` directory with the tracked result tables, and a `*_REPORT.md`
with the full results. Departures from the protocols are recorded in
[`experiments/revision_1/deviations.md`](../experiments/revision_1/deviations.md).
The planning documents that the protocols cite are internal and are not
distributed; each protocol and report is self-contained.

All runs used one host (32 CPU cores, 125 GiB RAM, one RTX 4090) inside the
project's Docker Compose workspace. Large outputs (dumps, metrics, analysis
stores) are not tracked; they are regenerated by the commands in
`experiments/revision_1/README.md`.

## Reliability grade (A1, A2)

- **Thresholds (A1).** Grades were recomputed from stored runs without new
  inference, with a vectorized grade engine that matches the stored grades
  for all 670,400 anchors at the default settings. Within the
  pre-registered ranges, the z threshold, the control-std estimator, a std
  floor, and the interval level keep agreement with the default grade at
  92.9 % or higher. A sign deadband changes up to 15 % of ImageNet grades,
  because an exact zero counts as a separate sign.
- **Structural findings (A1).** With every operator evaluated,
  `multi_strategy` is implied by `sign_consistent`, and every ImageNet
  region interval excluded zero, so the ImageNet grade was determined by
  `sign_consistent` and `exceeds_control`. NTU runs have no matched
  controls and cannot reach HIGH.
- **Control count (A2).** Three runs with 20 controls per anchor (2,000
  ImageNet images under both protocols, and the synthetic set) were regraded
  with subsets of K controls. With K=3, 8 % of anchor grades change between
  two random control draws (3 % at K=10). The fixed z threshold is easier to
  pass when the control spread is estimated from few values, so HIGH at K=3
  should be read as a candidate. The synthetic shortcut patch is HIGH at
  every K and every threshold.

The defaults are unchanged in 1.0.1. Report the HIGH share together with the
number of controls and the threshold, and report the continuous
`z_vs_control` alongside the grade.

## Architectures and preprocessing (A3, B1)

- **A3.** The case-study configuration was rerun with only the model name
  changed (`convnext_tiny.fb_in1k`, `deit_small_patch16_224.fb_in1k`); items,
  masks, and seeds were verified to equal the MobileNetV2 runs. DeiT-S uses
  a different official crop ratio (0.9), so cross-architecture comparisons
  use the crop-free runs. Under crop-free preprocessing, Gaussian noise gives
  a flat, reversed profile for DeiT-S, which the multi-operator check made
  visible (post hoc table, deviation D-007).
- **B1.** About 1.15 % of images have border cells entirely outside the
  official crop; masking them does not change the model input, yet some are
  graded HIGH. Effective-area-matched controls are not a practical fix under
  the official crop: corner targets get no matched control even with 20
  draws.

## Cost (A4)

- 41 timed audits over the number of samples (250-4,000), grid size (2x2 to
  8x8), controls (0-20), and operator conditions (1-7). A planner
  inefficiency found in C1 was fixed in 1.0.1, and four settings were
  measured again; the per-evaluation cost above is the fixed value.
- The model forward pass is 0.14 ms per evaluation; per-item CPU
  preprocessing and preparation dominate.
- `analyze` needs about 18 GiB per million evaluations; data-loading workers
  reached 104-110 GiB with an 8x8 grid or 20 controls. Beyond a few million
  evaluations on a 125 GiB host, use coarse-to-fine refinement or sample
  subsets, and run `ssat estimate` first (its run-time prediction was within
  +-25 % for 14 of 15 settings).

## Captum comparison and its limitation (C1)

- **Synthetic setting.** Runtime, memory, and storage were added to the
  existing comparison ([Reference comparison](REFERENCE_COMPARISON_CAPTUM_v1.md)).
- **Second setting (ImageNet).** 1,000 validation images, MobileNetV2-0.5,
  crop-free, 4x4 grid, 5 operator conditions, 3 controls per cell. The
  Captum workflow was adapted from the synthetic one (419 lines added or
  changed); SSAT needed two configuration lines. The deterministic operators
  give the same 16-cell rankings in both workflows.
- **Speed is a limitation of the current design.** SSAT perturbs each item
  in source space on the CPU and applies the model's own preprocessing per
  item. One pipeline serves every region kind (grid cells, explicit masks,
  matched controls, frame-dependent skeleton body parts on video), every
  operator, and every adapter, but it leaves the GPU mostly idle. Region
  masks, including skeleton body-part masks, could be composited on the GPU;
  a GPU pipeline, as the default or as an option where the regions,
  operators, and adapter allow it, is planned.
- Setup or implementation time was not measured: it depends on the
  implementer and cannot be compared between people. The comparison reports
  code size, changes, commands, and capabilities instead.

## Software changes in 1.0.1

- `PlanBuilder.materialize` builds a sample's work items once per sample
  instead of once per chunk. Item IDs, chunk IDs, and dumps are unchanged;
  runs with many items per sample are faster (the synthetic C1 workflow went
  from 1,207 s to 389 s).
